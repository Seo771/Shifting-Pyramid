# 미로 생성·변경 생명주기

현재 구현의 실행 순서와 상태 보존 기준이다. 이전 설계 문서의 `GeometryChanged` 후처리 설명보다 이 문서가 우선한다.

## 책임

- `MazeGrid`, Generation, RuntimeChange, Validation: Unity 오브젝트 없이 배치·연결·보호·도달성을 계산한다.
- `MazeTestBootstrapper`: 초기 생성/전체 재생성과 준비 완료 상태를 관리한다. 기존 컴포넌트 이름과 `BuildTestMaze()`는 씬 및 호출 호환을 위해 유지한다.
- `MazeRuntimeChangeController`: 주기와 캐릭터 좌표를 계산 계층에 전달하고, 확정된 변경을 Bootstrapper에 적용한다.
- `MazeRenderer`: 프리팹과 벽 표시, 격자/월드 좌표 변환을 담당한다.
- 게임의 Map / Box / Torch 및 `MazeNavMeshUpdater`: 각자 상태와 후처리를 담당한다. 계산 계층은 이들을 알지 못한다.

## 상태 보존 규칙

| 대상 | 초기 생성·전체 재생성 (`RebuildMaze`) | 플레이 중 부분 변경 |
| --- | --- | --- |
| 통로·방·출구 | 새 격자 및 프리팹 생성 | 일반 통로 일부와 안전한 특수방 최대 하나만 변경 |
| 저주 단지 방·획득 오브젝트 | 새 프리팹으로 초기화 | 기존 인스턴스·획득 상태 유지 |
| 특수방 퀴즈 상태 | 새 인스턴스로 초기화 | 교체되지 않은 방은 유지; 교체한 방은 새 인스턴스 |
| 일반 길목 상자 | 이전 상자 제거 후 새 배치 | 개봉 상자는 비활성 상태 유지. 미개봉 상자와 선택된 보상은 유지하고 필요 시 이동 |
| 횃불 | 새 배치 | 현재 벽 기준으로 전부 재배치 |
| 지도 탐험 | 전부 미탐험으로 초기화 | 구조가 바뀐 칸만 미탐험으로 전환 |
| 플레이어 위치 | 시작점으로 이동 | 유지 |
| 체력·인벤토리·승패·획득 개수 | 변경하지 않음. **맵 재생성은 새 게임이 아님** | 유지 |

새 게임은 별도의 게임 흐름에서 체력·인벤토리·저주 단지 개수 등을 함께 초기화해야 한다. 진행 중 맵만 재생성하면 단지 오브젝트와 획득 개수가 어긋날 수 있으므로 `RebuildMaze`를 재시작 버튼에 단독 연결하지 않는다.

## 실행 순서

초기 생성은 방 선택 → 3×3 방 예약 → 방 단위 DFS → 출구 배치 → BFS 검증 → 프리팹 생성 → 플레이어 배치 순서다. 저주 단지 방과 특수방은 90도 회전을 지원하고 방 사이에 한 칸을 남긴다. 출구는 시작점에서 가장 먼 도달 가능한 가장자리 일반 칸(1×1)이다.

프리팹이 준비된 후 `MazeUpdatePipeline`의 다음 단계를 동기적으로 실행한다.

1. `Preparing`: 이전 횃불을 제거해 상자 배치의 물리 검사에서 제외.
2. `ContentsUpdating`: 일반 길목 상자 생성 또는 재배치.
3. `DecorationsUpdating`: 상자 배치가 끝난 위치를 고려해 횃불 재배치.
4. `NavigationUpdating`: 물리 Transform 동기화 후 NavMesh 생성.

모든 단계가 끝난 뒤에만 `IsMazeReady = true`가 된다. 전체 재생성은 `MazeReady`로 새 지도 상태를 만들고, 부분 변경은 `MazeChanged(grid, changes)`로 기존 지도 상태를 갱신한다. 이벤트를 구독한 순서와 `LateUpdate`에 단계 간 순서를 맡기지 않는다.

`MazeRenderer.GeometryChanged`는 프리팹/벽 반영 신호일 뿐 전체 준비 완료가 아니다. 상자·횃불·지도·NavMesh는 더 이상 이 이벤트에 후처리를 연결하지 않는다.

설정/배치/경로/플레이어 소스 검증은 기존 표시를 지우기 전에 수행한다. 후처리 중 예외가 발생하면 뒤 단계를 실행하지 않으며 준비 미완료 상태를 유지한다. 표시와 콘텐츠 전체의 트랜잭션 롤백은 구현하지 않았다. 다음 전체 재생성으로 복구할 수 있다.

## 부분 변경 및 보호

- `MazeRegionChanger`는 서로 겹치지 않는 정사각 구역 안의 변경 가능한 일반 칸 사이 연결만 다시 만든다. 경계·방·출구·캐릭터 보호 칸을 보존하고 전체 도달성 검증 실패 시 해당 시도를 복구한다.
- 실행기는 현재 격자의 복사본에서 한 주기의 변경을 계산한다. 계산이 끝난 뒤 현재 격자 객체의 상태만 갱신하므로 지도 구독과 기존 방 인스턴스 연결은 유지된다. 계산 중 예외가 나면 원본은 바뀌지 않는다.
- `SpecialRoomReplacer`는 후보별 복사본에서 시도하고 검증 성공 시 확정한다. 캐릭터 보호 영역 주변 방은 교체하지 않는다.
- 한 주기의 특수방 교체와 여러 통로 변경은 각각 성공 가능한 부분을 적용한다. 요청 횟수 전체가 성공해야 하는 원자적 변경은 아니다.
- 실행기는 모든 활성 `MonsterAI`와 기존 Inspector의 `Mummy` 참조를 `MazeProtectedArea` 좌표/반경으로 전달한다. 미라가 미로 밖에 있으면 해당 주기를 건너뛰고 경고한다.
- 설정의 변경 횟수는 목표 상한이다. 20×20에서 9×9 구역 5개는 불가능하므로 현재 값은 4로 수정했다. 보호 영역과 배치에 따라 실제 변경 수는 더 적을 수 있다. `LastChangedRegionCount`로 실제 횟수를 확인한다.
- `TryChangeNow()`는 타이머와 동일한 변경 경로를 수동으로 실행한다. 컴포넌트의 `Try Change Maze Now` 메뉴에서도 호출한다. 결과는 반환값, `LastChangedRegionCount`, `LastChangeMessage`로 확인한다. 건너뛰거나 실패하면 이전 성공 횟수를 남기지 않는다.
- 교체 프리팹/표시 참조는 데이터 확정 전에 검증한다. 계획 단계 오류는 원본을 유지하며, 표시/후처리 단계 오류는 준비 미완료 상태로 남긴다.

## 변경 좌표와 공용 바닥

`MazeChangeSet`은 벽·타일 종류·보호 여부·방 점유가 바뀐 좌표를 보관한다. 공유 벽 양쪽과 교체한 방의 점유 칸을 포함한다. 렌더러와 지도는 이 목록을 사용한다. 변경 계획용 격자 복사는 주기당 한 번이며, 특수방 교체 후보 검증에서는 기존처럼 별도 복사본을 사용한다.

`ShiftingPyramid.Game.World.MazeFloor`는 지도와 상자 배치가 공유하는 바닥 콜라이더 표식이다. 이전 `MapFloor`의 스크립트 GUID를 유지하고 `MovedFrom`을 지정했으므로 기존 프리팹 연결은 유지한다.

상자 전체 배치 검토, 횃불 재생성, NavMesh 전체 빌드는 유지한다. 추가 최적화는 Unity Profiler로 비용을 측정한 뒤 진행한다.

## 검증

- `Tests/MazeCoreChecks`: 기존 생성·회전·변경·교체·보호·도달성·롤백 검사와 변경 좌표, 후처리 순서, 재진입/실패, 다중 캐릭터 보호 검사.
- `Tests/MapExplorationChecks`: 탐험 상태와 증분 변경 좌표 기반 지도 무효화 검사.
- `Assets/Editor/MazeLifecycleSmokeCheck.cs`의 배치 전용 검사로 MainScene 헤드리스 Play Mode를 실행했다. 초기 생성, 상자/단지 획득, 부분 변경 시 개봉 상태·진행도·지도 객체 유지, 전체 재생성, 설정/방 참조 실패 시 원본 보존, 후처리 실패 후 복구, Missing Script 부재, 각 단계의 실제 NavMesh 시작점→출구 경로를 통과했다. 씬과 설정 에셋은 저장하지 않고 복제 설정만 사용한다. 실행법은 `../Tests/README.md`에 있다.
- 미라 프리팹의 끊어진 `MonsterAI` 스크립트 GUID를 현재 코드로 복구했다. 다만 처음 씬 로드 시 아직 NavMesh가 없어 발생하는 Agent 초기화 경고는 남아 있다. 최종 NavMesh 생성과 출구 경로 검사는 통과하며, 초기 미라 배치/활성화 시점 정리에서 다룬다.
- 헤드리스 검사는 렌더링/애니메이션 품질, 직접 조작, 횃불 시각적 겹침, 미라의 장시간 이동, 프레임 성능을 검증하지 않는다. 이 항목은 수동 Play Mode와 Profiler로 확인해야 한다.
