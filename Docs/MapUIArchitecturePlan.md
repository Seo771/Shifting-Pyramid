# 맵 UI 아키텍처 설계

## 1. 범위와 결정

이 문서는 구현 전 설계다. 현재 프로젝트에 맵 UI나 탐험 기록이 구현되어 있다는 뜻이 아니다. 맵은 게임 전용 UI로 만들고 미로 생성·변경 알고리즘에는 맵 표시나 플레이어 탐험 상태를 넣지 않는다.

- 원형 미니맵은 화면 한쪽에 고정한다. 북쪽은 항상 위쪽이며 플레이어 마커는 중앙에 고정한다. 플레이어의 연속적인 이동량만큼 지도 내용이 반대 방향으로 움직인다.
- `M` 키로 화면 대부분을 덮는 전체 맵을 토글한다. 전체 맵은 북쪽 고정, 전체 격자 맞춤 보기이며 같은 탐험 기록을 사용한다. 열려 있는 동안 게임을 일시정지한다.
- 플레이어가 발로 밟은 격자 칸만 공개한다. 공개되지 않은 칸은 두 맵 모두 바닥·벽·방 종류·출구 정보를 표시하지 않는다. 점프 중 지나간 칸은 공개하지 않는다.
- 미로의 실제 구조가 바뀐 칸은 다시 미탐험으로 만든다. 재방문하면 변경된 구조가 보인다. 미로 변경 시도만 있었거나 결과가 동일한 칸은 유지한다.
- 3x3 방도 칸별로 공개한다. 내부 벽의 정확한 형상은 현재 논리 데이터에 없으므로 1차 맵은 방 내부 구조를 추측해서 그리지 않는다.
- 1차 범위에서 몬스터 위치, 길 안내, 자동 경로 탐색, 개별 저주 단지의 획득 위치 표시는 하지 않는다. 단순한 방/출구 구분도 해당 칸을 밟은 뒤에만 가능하다.

## 2. 현재 코드에서 확인한 사실

| 위치 | 지금 제공하는 것 | 맵 UI에 필요한 추가 사항 |
| --- | --- | --- |
| `Assets/Script/Maze/Core/MazeGrid.cs`, `MazeTile.cs`, `MazeRoom.cs` | 격자 크기, 타일 좌표와 네 방향 개방 상태, 타일 종류, 3x3 방의 점유 칸·원점·템플릿 인덱스·회전 | 탐험 여부와 과거 구조 스냅샷은 없음 |
| `Assets/Script/Maze/View/MazeRenderer.cs` | 월드 위치를 정수 격자로 변환, 좌표의 월드 중심 조회, 표시 갱신 후 `GeometryChanged` 발생 | 미니맵의 부드러운 스크롤에 쓸 연속 격자 위치 조회는 없음; 이벤트에 변경 좌표는 없음 |
| `Assets/Script/Maze/View/MazeTestBootstrapper.cs` | 시작 시 생성·검증·표시, `CurrentGrid`, `Renderer`, `PlayerTransform` 공개 | 성공적으로 초기화되고 플레이어가 배치된 뒤의 완료 신호는 없음 |
| `Assets/Script/Maze/View/MazeRuntimeChangeController.cs` | 플레이어 위치를 기준으로 특수방 교체와 통로 구역 변경 시도, 성공 시 `Refresh` 호출 | 맵 전용 이벤트는 없음. 변경 실패 시 `Refresh`하지 않음 |
| `Assets/Script/Player/PlayerMazeSpawner.cs`, `Assets/Prefab/PlayerT.prefab` | 시작 칸 배치, 실제 플레이어 `Transform`, `CharacterController` | 발 접촉 칸을 기록하는 컴포넌트는 없음 |
| `Assets/Script/Game/GameManager.cs` | 저주 단지 개수·출구 개방·승패 상태 | 개별 단지의 월드/격자 위치 기록은 없음 |
| `Assets/Scenes/MainScene.unity` | Screen Space UI Canvas, 카운트다운, 상태 UI, 공용 알림, 결과 패널 | 미니맵·전체 맵 오브젝트는 없음 |

현재 설정 에셋의 미로 크기와 방 개수는 테스트 중 바뀔 수 있으므로 지도 크기를 상수로 고정하지 않는다. 메인 씬의 `MazeRuntimeChangeController.mummy`는 현재 비어 있지만 맵 기능의 필수 입력은 아니다. 기존 인수인계 문서의 '런타임 변경 미구현' 같은 서술은 현재 코드와 다르다.

## 3. 책임과 데이터 흐름

맵 기능은 `Assets/Script/Game/Map/` 같은 게임 전용 위치에 둔다. 아래 이름은 구현 시 사용할 책임 단위이며, 실제 파일 분리는 해당 단계의 복잡도에 맞춘다.

| 책임 | 역할 |
| --- | --- |
| `MapExplorationState` | 현재 미로의 크기, 칸별 공개 여부, 마지막으로 확인한 구조 값 보관. 미로 데이터는 읽기만 한다. |
| `MapDiscoveryTracker` | 미로 준비 완료 후 플레이어의 접지 상태와 발 위치를 읽어 새 칸을 공개한다. |
| `MapTileSignature` | 칸별 구조 비교에 쓰는 변경 불가능한 값 데이터. `MazeTile`/`MazeRoom` 객체 참조를 그대로 저장하지 않는다. |
| `MapGridView`와 `MapTileView` | 공유 상태를 UI 타일·벽·방/출구 표시로 그린다. 미니맵과 전체 맵에 같은 뷰 로직을 두 번 사용한다. |
| `MapScreenController` | `M` 입력, 전체 맵 열기/닫기, 일시정지와 입력/커서 상태 복원을 담당한다. |

`MazeGrid` -> 구조 값 스냅샷 -> `MapExplorationState` -> 미니맵/전체 맵 순서로 흐른다. 플레이어 발 위치는 별도로 탐험 상태에 반영한다. 두 화면은 서로 다른 탐험 배열을 갖지 않는다. 프레임마다 전체 UI를 다시 만들지 않고, 공개/무효화된 칸만 갱신한다. 플레이어 마커와 미니맵 스크롤만 이동 중 갱신한다.

## 4. 초기 생성과 변경 이벤트

현재 `MazeTestBootstrapper.BuildTestMaze()`는 `mazeRenderer.Build()`를 호출한 **후** `currentGrid`를 대입하고 플레이어를 배치한다. `Build()` 안에서 `GeometryChanged`가 먼저 발생하므로 그 이벤트만으로 초기 맵을 구성하면 `CurrentGrid`가 아직 `null`이거나 이전 미로일 수 있다.

구현 시 `MazeTestBootstrapper`에 초기화 완료 신호(예: `MazeReady`)를 추가한다. `currentGrid`, 방 목록, 시드 대입 및 `SpawnAtStart`가 끝난 뒤 한 번 발행한다. 맵 구독자는 활성화될 때 신호를 구독하고, 이미 준비된 `CurrentGrid`가 있으면 즉시 초기화한다. 초기화에서는 이전 탐험 기록을 지우고 모든 칸의 구조 스냅샷을 저장한다. 아직 어떤 칸도 공개하지 않으며 이후 접지 판정이 시작 칸을 공개한다. `BuildTestMaze()`가 다시 성공하면 새 미로로 완전히 초기화한다. 실패하면 기존 상태를 새 지도로 오인하지 않는다.

런타임에는 `MazeRenderer.GeometryChanged`를 구조 반영 완료 신호로 구독한다. 현재 컨트롤러는 특수방 교체와 여러 구역의 벽 변경을 적용한 다음 `Refresh()`를 한 번 호출하므로 그 시점에 전체 격자를 스캔해 이전 스냅샷과 비교한다. 초기 `Build()`가 내보내는 같은 이벤트는 새 `MazeReady` 처리 전에는 무시한다. 더 큰 미로에서 성능 문제가 실제로 나타나기 전까지 별도 변경 좌표 이벤트를 미로 알고리즘에 추가하지 않는다.

## 5. 탐험 및 구조 변경 판정

탐험 상태는 `bool[width, height]` 또는 동일한 좌표 기반 배열이다. 구조 스냅샷은 같은 크기의 값 배열이며 각 칸에서 다음을 비교한다.

1. 북·동·남·서 네 방향의 개방 비트.
2. `MazeTileType` (`Normal`, `CurseJarRoom`, `SpecialRoom`, `Exit`).
3. 방 점유 칸이라면 방 원점, `TemplateIndex`, `RotationQuarterTurns`. 일반 칸은 '방 없음'으로 저장한다.

`IsProtected`는 지도 형상을 나타내지 않으므로 비교 대상에서 제외한다. 방 프리팹 이름이나 Unity 인스턴스 ID도 비교하지 않는다. 방 출입구가 템플릿/회전에 의해 정해진다는 현재 모델을 전제로 한다. 나중에 같은 템플릿 인덱스에서 출입구 구성이 런타임에 바뀌면 그 값도 서명에 추가해야 한다.

변경 이벤트마다 모든 칸의 새 서명을 만든다. 이전 서명과 다른 칸만 `explored=false`로 만들고, 화면에서 그 칸의 기존 바닥·벽·아이콘을 즉시 숨긴 뒤 스냅샷을 새 값으로 갱신한다. 원래 탐험하지 않은 칸은 그대로 숨긴다. 통로 양쪽의 공유 벽이 바뀌면 양쪽 칸의 비트가 달라지므로 양쪽을 무효화한다. 어느 한쪽이 미탐험이면 공개된 쪽에서도 미탐험 이웃의 정보를 새로 유추해 그리지 않는다. 기존 타일이 그대로라면 단지 '변경 구역에 포함됐다'는 이유로 지우지 않는다.

특수방 이동 시 이전 3x3 자리는 방에서 일반 칸으로, 새 3x3 자리는 일반 칸에서 방으로 바뀐다. 두 발자국의 각 칸을 서명으로 비교하므로 실제로 바뀐 칸만 숨긴다. 플레이어가 변경된 칸 위에 서 있는 예외 상황에서는 무효화가 먼저 일어나고, 그다음 접지 판정에서 현재 칸만 재공개한다. 미로 재생성은 변경이 아니라 새 지도이므로 이전 탐험 기록을 전부 버린다.

## 6. 발 접촉 판정과 지도 좌표

`PlayerMazeSpawner.PlayerTransform`에서 현재 플레이어를 받고, 그 오브젝트의 `CharacterController`를 확인한다. 플레이어 이동의 `Update`/`CharacterController.Move`가 끝난 뒤 `LateUpdate`에서 `isGrounded`를 검사한다. 접지 중일 때만 `CharacterController.bounds`의 바닥 중심 XZ를 `MazeRenderer.TryGetCoordinate()`에 넣어 해당 칸을 공개한다. 컨트롤러가 없거나 비활성, 공중에 있거나 좌표가 미로 밖이면 공개하지 않는다. 시작 직후 아직 접지 판정이 확정되지 않았다면 첫 접지 프레임에 공개한다. 다른 물체 위에 선 것만으로 칸이 공개되지 않도록 발밑 아래 방향의 짧은 검사로 실제 미로 바닥 콜라이더를 확인한다. 이를 위해 일반 타일과 3x3 방의 바닥 콜라이더에 공통으로 적용할 레이어/마스크 규칙을 씬·프리팹 연결 단계에 포함한다.

칸 경계에서는 월드 좌표를 정수 격자로 변환하는 현재 `MazeRenderer` 규칙을 그대로 따른다. 경계 흔들림이 실제 플레이에서 발견되면 짧은 안정화/히스테리시스를 게임 쪽에 추가하되, 공중 이동을 공개하는 방식으로 우회하지 않는다. 접지와 바닥 검사의 조합은 실제 접촉 이력 전체를 기록하는 방식은 아니므로, 프리팹 바닥 높이와 작은 단차에서의 판정을 Play Mode에서 확인한다.

미니맵의 위치는 정수 칸만 따라가면 계단식으로 튄다. `MazeRenderer`의 타일 루트·중앙 정렬·크기 계산을 UI가 중복 구현하지 않도록, 구현 단계에서 읽기 전용 연속 격자 위치 변환을 `MazeRenderer` 표시 계층에 추가한다. 이를 플레이어의 UI 좌표로 바꿔 지도 컨텐츠를 부드럽게 이동시키고 중앙의 플레이어 화살표는 고정한다. 화살표만 플레이어 수평 방향으로 회전한다. 전체 맵에서는 같은 좌표를 사용해 화살표를 실제 칸 위에 놓는다. 격자 Y 증가는 화면 위쪽(북쪽)으로 대응한다.

## 7. Unity UI 구성

기존 `UI Canvas` 아래에 두 영역을 추가한다. 미니맵은 원형 `Image + Mask` 안에 격자 타일 컨텐츠를 넣고, 플레이어 화살표를 마스크 위 중앙에 둔다. 원형 외부에서는 어떤 타일도 보이지 않아야 한다. 전체 맵은 기본 비활성인 화면 오버레이, 어두운 배경, 안전 여백 안에 맞춰지는 격자 컨텐츠, 플레이어 화살표, 닫기 컨트롤로 구성한다. 임의 해상도에서 타일은 정사각형을 유지하고 지도의 긴 변 기준으로 컨텐츠를 맞춘다.

각 UI 타일은 고정 크기 바닥과 네 방향 벽 선분을 표현한다. 미탐험 칸의 바닥/벽/방 표시를 전부 비활성화한다. 공개된 일반 통로는 현재 스냅샷의 벽을 표시한다. `Exit` 및 방 종류 표시는 그 칸이 공개된 후에만 나타나며, 미탐험 이웃이나 방의 나머지 칸까지 밝히지 않는다. 플레이어 화살표는 현재 위치 확인용으로 항상 표시할 수 있지만 주변의 숨겨진 타일 정보를 드러내지 않는다.

3x3 방의 현재 논리 격자는 내부 칸이 연결돼 있다고 가정하지만 실제 프리팹 내부 벽·장식의 형상을 저장하지 않는다. 1차 지도에서는 방문한 칸을 방 바닥으로 표시하고 확인 가능한 외곽/출입구만 그린다. 내부 통로가 모두 열려 있다고 그리거나 정확한 실내 평면도라고 주장하지 않는다. 정밀한 방 내부 지도가 필요해지면 프리팹에 별도 맵 표현 데이터를 작성하는 후속 작업으로 분리한다.

## 8. 전체 맵과 일시정지

`M`은 현재 게임 스크립트에서 사용하지 않는다. 전체 맵을 열 때 플레이 중인지 확인하고, 이전 `Time.timeScale`, `Cursor.lockState`, `Cursor.visible`을 저장한다. `Time.timeScale=0`으로 게임 시간을 멈추고 커서를 풀어 표시한다. 닫기 버튼과 `M` 입력은 정지 상태에서도 처리되도록 `Update`/실시간 UI 경로를 사용한다. 닫을 때 저장한 값으로 복원한다. 맵을 열지 않은 상태에서 임의의 시간·커서 값을 덮어쓰지 않는다.

`Time.timeScale=0`만으로는 입력 함수 호출 자체가 막히지 않는다. 전체 맵이 열린 동안 플레이어 이동, 시점 회전, 상호작용, 핫바 사용/선택 입력에 게임 계층의 작은 입력 가드를 둔다. 현재 `PlayerMovement`, `MouseLook`, `PlayerInteractor`, `HotbarController` 및 실제 씬에서 쓰는 이동 컴포넌트를 연결 전 확인한다. UI 닫기 입력은 유지한다. `Escape`는 현재 핫바 취소에 쓰이므로 1차 토글 키로 사용하지 않는다.

맵이 열린 채 승리/패배, 오브젝트 비활성화, 씬 종료가 일어나면 맵을 닫고 자신이 설정한 일시정지·커서·입력 상태를 복원한다. 현재 `GameManager`는 `IsGameFinished`를 공개하므로 맵 컨트롤러가 열린 동안 상태를 확인해 종료 시 닫는다. 다른 일시정지 기능이 추가되면 서로의 값을 덮어쓰지 않도록 단일 소유 규칙을 먼저 정한다. 일시정지 중 미로 변경 타이머와 미라화 수치가 증가하지 않는지 확인한다. 맵을 닫은 뒤 정지 전의 속도로 재개돼야 한다. `GameNotice`는 실시간 대기 코루틴을 사용하므로 맵 일시정지 중에도 알림이 사라질 수 있으며, 이 동작은 UI 테스트에서 확인하고 필요할 때만 별도 조정한다.

## 9. 구현 순서와 완료 기준

1. **데이터와 준비 신호:** 초기 `MazeReady` 시점 정의, 값 스냅샷과 탐험 배열, 재생성 초기화 구현. 변경 전/후 서명 비교를 EditMode 또는 독립 로직 테스트로 확인한다. 미로 계산 코드는 변경하지 않는다.
2. **발견 추적:** `CharacterController.isGrounded`, 발 위치, 미로 바닥 콜라이더 확인으로 방문 칸만 공개. 일반/방 바닥 레이어를 연결하고 시작 칸, 걸어서 이동한 칸, 점프해 건너뛴 칸, 다른 물체 위에 선 경우를 수동 테스트한다.
3. **원형 미니맵:** 칸/벽 UI, 원형 클리핑, 북쪽 고정, 중앙 화살표, 부드러운 이동을 구현한다. 화면 비율을 바꿔도 원형 밖 정보가 보이지 않고 화살표가 중앙에 남는지 확인한다.
4. **전체 맵:** 같은 탐험 상태의 두 번째 뷰와 `M` 토글·닫기 버튼·일시정지/복원을 연결한다. 전체 맵에서 미탐험 정보가 나타나지 않고, 열린 동안 이동/시점/상호작용/핫바/미로 타이머가 멈추는지 확인한다.
5. **변경 무효화:** 열린 통로 벽 변경, 변경 실패, 같은 상태로 귀결된 칸, 특수방 이전/새 위치, 재방문을 확인한다. 두 맵이 같은 프레임에 같은 탐험 결과를 보여야 한다.
6. **씬·수명 검증:** 미로 생성 실패와 재시도, 맵을 연 상태의 승패·씬 전환, 비활성화, 플레이어 참조 재획득, 다른 해상도를 확인한다. Unity Play Mode 검증 전에는 완료로 표시하지 않는다.

자동 테스트는 서명 비교·탐험 무효화 같은 순수 상태 로직에 집중하고, 접지·UI 마스크·입력 차단·일시정지 복원은 씬에서 수동 검증한다. 기존 `Tests/MazeCoreChecks`는 미로 생성·변경 검증용이며 맵 UI 테스트를 대신하지 않는다.

## 10. 공개용 미로 알고리즘과의 경계

`MapExplorationState`, UI 뷰, 입력·일시정지, 플레이어 발견 추적은 전부 게임 전용이다. 공개용으로 분리할 미로 Core/Generation/RuntimeChange/Validation에는 플레이어 방문 기록이나 uGUI 타입을 넣지 않는다. 필요한 작은 통합 신호와 연속 좌표 변환은 Unity 표시·부트스트랩 계층에만 둔다. 맵 UI를 제거해도 미로 생성, 변경, 검증, 렌더링이 그대로 동작해야 한다.
