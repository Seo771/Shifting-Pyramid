# 일반 길목 BOX 배치 설계

현재 갱신 순서는 [미로 생명주기](MazeLifecycle.md)를 따른다. 상자는 `GeometryChanged`/`MazeReady` 구독 대신 파이프라인의 `ContentsUpdating` 단계에서 처리한다. 바닥 표식은 공용 `Game.World.MazeFloor`이며, 횃불 제거 후 상자를 배치하고 이후 횃불·NavMesh를 갱신한다.

상태: 최초 배치와 미로 변경 후 재배치 코드 구현, Play Mode 검증 대기. 이 문서는 랜덤 아이템 BOX의 자동 배치와 미로 변경 시 수명 규칙을 정한다. 횃불 배치는 별도 설계로 다룬다.

## 목표

- BOX는 미로의 일반 길목에만 드물게 등장한다. 시작점, 출구, 저주 단지 방, 특수방 및 그 3×3 점유 영역에는 배치하지 않는다.
- 같은 미로를 여러 번 생성해도 이전 BOX가 남거나 중복 생성되지 않는다.
- 미로 변경으로 BOX 자리가 방이 되거나 통행·상호작용이 어려워지면 **미개봉 BOX만** 유효한 길목으로 옮긴다. 이미 연 BOX는 다시 등장하지 않는다.
- BOX 배치와 보상 상태는 게임 전용 코드에 두고, 공개할 미로 Core/Generation/RuntimeChange/Validation 알고리즘에는 넣지 않는다.

## 현재 구현에서 재사용할 것

| 요소 | 확인한 상태 | 배치에 필요한 추가 작업 |
| --- | --- | --- |
| `Assets/Prefab/item/item_box.prefab` | `RandomBox`, `BoxCollider`와 아이템 확률 목록이 있다. 루트 위치는 원점이며 크기 `(2.051895, 1, 1.0321)`이다. | 생성 시 타일 위치·회전·바닥 높이를 명시적으로 설정하고 실제 통행 폭을 확인한다. |
| `RandomBox` | 보상 지급 성공 시에만 개봉하며 `Opened` 이벤트를 보내고 BOX를 비활성화한다. 지급 실패 후 재시도할 때는 선택된 보상을 유지한다. | 배치 관리자는 이벤트로 개봉 기록을 저장한다. |
| `PlayerInteractor` | 반경 `interactionRange = 2.5`의 콜라이더에서 `IInteractable`을 찾고 G키로 사용한다. | 놓인 위치와 방향에서 실제로 가까이 접근·사용할 수 있는지 확인한다. |
| `MazeGrid`, `MazeTile` | `TileType`, `IsProtected`, 네 방향 통로 연결과 `TryGetRoom`을 제공한다. | BOX 상태를 격자에 저장할 필요는 없다. |
| `MazeRenderer` | `TryGetTileWorldPosition()`으로 타일 중심을 얻고 표시 후 `GeometryChanged`를 발생시킨다. | 별도 게임용 BOX 루트를 사용한다. 타일/방 프리팹 안에 BOX를 박아 넣지 않는다. |
| `MazeTestBootstrapper` | 검증·렌더링·플레이어 배치 완료 뒤 `MazeReady`를 보낸다. | BOX 최초 배치와 재생성 초기화는 이 신호를 기준으로 한다. |
| `MazeRuntimeChangeController` | 특수방 교체와 통로 변경이 실제로 일어나면 `renderer.Refresh()`를 호출한다. | `GeometryChanged`를 받은 BOX 관리자가 새 격자에서 기존 자리의 유효성을 다시 검사한다. |

현재 `MazeBalanceSettings.asset`은 20×20 미로, 저주 단지 방 1개, 특수방 1개로 설정돼 있다. 이 값은 변경 가능한 밸런스 설정이므로 배치 개수와 좌표를 코드에 고정하지 않는다. 기존 `iteam_Tile.prefab`에는 BOX가 들어 있지만 현재 미로 생성이 쓰는 일반 타일 프리팹은 `Default_Tile.prefab`이다. 새 배치 시스템은 `iteam_Tile`에 의존하지 않는다.

## 배치 설정과 책임

BOX 프리팹, 목표 개수, 시작점 제외 거리, BOX 간 최소 격자 거리, 벽 여유, 최소 통행 폭을 게임 전용 `MazeBoxPlacementController`의 Inspector 필드로 노출한다. 미로 알고리즘만 분리할 때 빠질 수 있도록 `MazeBalanceSettings`에는 넣지 않는다. 현재 MainScene 설정은 목표 6개, 시작점 제외 거리 3칸, BOX 사이 최소 거리 4칸이다. 이 수치는 Play Mode에서 조정한다.

예상 컴포넌트는 `Assets/Script/Game/Box/`에 둔다.

| 컴포넌트 | 책임 |
| --- | --- |
| `MazeBoxPlacementController` | `MazeReady`·`GeometryChanged` 구독, 최초 선정, 변경 후 유효성 검사·재배치, 재생성 시 정리 |
| `RandomBox` | 아이템 추첨·지급, 개봉 결과 통지. 격자 좌표 선택이나 미로 변경 판단은 하지 않음 |

배치 관리자는 현재 `MazeGrid`와 생성된 BOX별 **격자 좌표, 인스턴스, 개봉 여부**를 가진다. `MazeGrid` 참조가 새 것으로 바뀌면 이전 기록과 인스턴스를 모두 정리하고 새 미로에 대해 다시 선정한다. 씬 전환·컴포넌트 비활성화 시 이벤트를 해제한다. `GeometryChanged`는 초기 `CurrentGrid` 대입보다 먼저 발생할 수 있으므로 초기 배치 신호로 사용하지 않는다.

## 초기 후보 선정

1. `MazeReady`를 받은 뒤, 범위 안의 모든 격자 칸에서 `Normal`이면서 방 점유 칸이 아니고 보호 칸·출구·시작점 제외 반경 밖인 칸만 고른다. 방 입구 바로 바깥 칸도 기본적으로 제외해 출입구를 막지 않는다.
2. 네 방향 연결을 검사한다. 막다른 길 또는 직선 통로를 우선하고, 갈림길·방 입구·플레이어가 꼭 통과해야 하는 좁은 칸은 제외한다. 실제 통로 폭과 BOX 콜라이더가 맞지 않으면 그 후보를 버린다.
3. BOX 간 최소 거리는 격자 좌표의 맨해튼 거리로 계산한다. 후보를 시드 기반 난수로 섞되, 같은 초기 미로 시드·설정이면 같은 칸을 고르게 한다. 이미 선택한 칸과 거리 규칙을 만족하는 후보만 채택한다.
4. 각 후보에서 바닥 높이, 벽·문·기존 배치물·플레이어 동선과의 충돌, 상호작용 거리, 최소 통행 폭을 물리 검사한다. 검사에 실패한 칸은 건너뛴다. 지정 개수를 채울 수 없다면 가능한 개수만 놓고 진단 로그를 남긴다. 검증을 우회해 강제로 놓지 않는다.

타일 중앙은 **후보 기준점**으로만 쓴다. 벽 쪽에 고정된 오프셋을 두고 상호작용 면은 열린 통로 쪽을 향하게 한다. 막다른 길은 입구 반대편 벽, 직선 길은 좌·우 벽 중 여유가 있는 쪽을 우선한다. 중앙에 두어도 플레이어와 몬스터의 통행 폭이 충분한 크기라면 오프셋 0을 허용한다. `TryGetTileWorldPosition()` 결과에 정해진 로컬 오프셋과 바닥 보정치를 적용하되, 프리팹 루트에 저장된 씬 좌표를 그대로 사용하지 않는다.

논리 경로 검증은 BOX 콜라이더에 막힌 실제 통행을 보장하지 않는다. 배치 후 플레이어 접근과 몬스터 이동을 Play Mode에서 확인해야 한다. NavMesh 재생성에 BOX가 불필요하게 포함되지 않도록 레이어 또는 `NavMeshModifier` 적용을 검토하되, 적용 전에 AI가 BOX를 통과하려는지 확인한다.

## 개봉과 미로 변경 규칙

- 배치된 BOX는 **보상 지급에 성공했을 때만** 개봉 완료로 기록한다. 아이템 후보가 없거나 핫바가 가득 차 지급에 실패하면 닫힌 상태를 유지한다. 성공 후에는 다시 보상을 뽑지 않으며, 화면에서 제거하거나 열린 외형을 남기더라도 `PlayerInteractor`의 재선택과 통행 방해가 없어야 한다.
- 미로 변경 후에도 미개봉 BOX의 칸이 일반 통로이고 기존 배치 방향·여유가 유효하면 그대로 둔다. 벽이 바뀌어 방향만 부적절하면 **같은 칸에서 위치·회전만 다시 계산**한다.
- 칸이 새 특수방의 3×3 영역, 방 입구, 보호 칸 또는 통행 불가 위치가 되면, 미개봉 BOX를 다른 유효한 일반 길목으로 옮긴다. 플레이어나 몬스터와 겹치지 않는 후보를 고르고, 먼저 기존 BOX 좌표를 후보 집합에서 제외해 중복을 막는다.
- 이동할 후보가 없으면 그 BOX를 보이지 않는 대기 상태로 두고 다음 실제 미로 변경 때 재시도한다. 보상 상태는 보존한다. 열린 BOX를 대신 채우거나 새 BOX를 무한히 생성하지 않는다.
- 변경에 실패했거나 BOX 주변의 실제 배치 가능 조건이 동일하면 BOX를 건드리지 않는다. `GeometryChanged`는 성공한 변경 후에만 발생하지만, BOX 관리자는 여전히 각 인스턴스의 유효성을 검사한다.
- 한 미로의 목표 BOX 수는 **초기 배치 개수**다. 플레이어가 BOX를 열수록 미개봉 개수는 감소한다. 미로 변경이 개봉한 BOX를 다시 채우지 않는다. 새 미로를 생성할 때만 개봉 기록을 초기화한다.

프리팹의 루트 원점은 BOX의 **중심**이며, 콜라이더 높이가 1이다. 배치할 때 바닥 면이 바닥 위에 오도록 높이를 보정한다. 보상이 지급된 BOX는 비활성화되고, 배치 관리자는 `RandomBox.IsOpened`를 확인해 그 인스턴스를 재배치 대상에서 제외한다. `Opened` 이벤트는 다른 게임 시스템이 개봉 결과를 사용할 때 구독할 수 있다.

## 이벤트 순서

```text
미로 생성 성공 → MazeRenderer.Build → CurrentGrid 대입 → 플레이어 시작 배치
             → MazeReady → 기존 BOX 기록 정리 → 후보 선정 → BOX 생성

실제 미로 변경 → 방 프리팹 교체/통로 벽 갱신 → GeometryChanged
             → 기존 미개봉 BOX 유효성 확인 → 유지/회전/이동/대기

새 미로 생성 성공 → 이전 BOX 모두 정리 → 새 MazeReady에 대해 재배치
```

미로 생성 실패에는 새 `MazeReady`가 나오지 않는다. 실패 전에 `IsMazeReady`가 꺼졌다면 기존 BOX를 숨기고, 이전 미로가 그대로 준비된 상태라면 기존 BOX도 유지한다. 어느 경우든 실패한 격자를 새 배치 대상으로 취급하지 않는다. 변경 중 BOX 재배치와 NavMesh 재생성의 이벤트 구독 순서는 고정돼 있지 않다. AI 충돌 확인이 필요하면 BOX 갱신과 NavMesh 빌드의 실행 순서를 별도 게임 계층에서 명시한다.

## 구현 단계와 완료 기준

1. **프리팹·상호작용 정리(코드 완료, Play Mode 확인 대기):** 프리팹 루트 원점과 지급 성공 뒤 개봉 완료 통지·중복 상호작용 차단을 구현했다. 빈 보상/가득 찬 핫바에서 닫힌 상태가 유지되는지, 실제 콜라이더 크기와 높이가 적합한지 확인한다.
2. **최초 배치(코드 완료, Play Mode 확인 대기):** `MazeReady` 이후 막다른 길·직선 길목을 골라 별도 BOX 루트에 생성한다. 시작점·출구·방·방 입구 제외, 개수 상한, 간격, 같은 시드 재현성을 검사한다.
3. **배치 품질(기본 검사 구현, Play Mode 확인 대기):** 닫힌 벽 쪽 오프셋, 바닥 높이, BOX 크기·장애물 충돌을 검사한다. 플레이어·몬스터 통행 및 G키 상호작용을 실제로 확인한다. 후보 부족 시 안전하게 적게 배치되는지 확인한다.
4. **런타임 변경(코드 완료, Play Mode 확인 대기):** 유효한 기존 자리는 유지하고 벽 방향이 바뀌면 같은 칸에서 위치·회전을 다시 계산한다. 새 방이나 장애물과 겹치면 미개봉 BOX 인스턴스를 다른 유효 길목으로 옮긴다. 후보가 없으면 비활성 상태로 보관해 다음 변경 때 다시 시도한다. 열린 BOX가 되살아나지 않는지 확인한다.
5. **재생성·씬 수명:** `BuildTestMaze()` 재호출, 컴포넌트 비활성화, 씬 재시작에서 중복·누락·이전 BOX 잔존을 검사한다.

첫 구현에서는 BOX 배치와 개봉 상태만 다룬다. 횃불, 미니맵 BOX 표식, 저장/로드, 몬스터의 BOX 상호작용은 범위 밖이다.
