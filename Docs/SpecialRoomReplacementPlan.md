# 동적 특수방 교체 설계

상태: 첫 버전 구현 완료, Unity Play Mode 확인 대기. 이 문서는 게임 중 특수방을 없애고 새 특수방을 등장시키는 규칙을 정한다.
특수방을 통째로 옮기는 기능이나 일반 타일의 벽만 바꾸는 기능과는 별개다.

## 목표와 기본 규칙

- 한 번의 변화에서 기존 특수방 `K`개를 제거하고 새 특수방 `K`개를 생성한다. 성공한 결과의 특수방 총수는 시작 시 설정한 `SpecialRoomCount`와 같다.
- 첫 버전은 미로 변경 주기마다 `K = 1`을 시도한다. 현재 설정 에셋의 특수방 수가 1개라면 그 방 하나가 교체된다. 이후 `K`와 실행 주기는 별도로 조절할 수 있다.
- 새 방은 가능하면 이전과 다른 위치 및 다른 프리팹을 선택한다. 프리팹 종류가 하나뿐이면 위치와 회전만 바뀔 수 있다.
- 유효한 교체를 찾지 못하면 이번 특수방 변화만 건너뛴다. 기존 방과 게임 오브젝트는 그대로 둔다.
- 보물방, 출구, 시작점은 교체 대상이 아니다. 기존의 일반 통로 변경은 여전히 방의 3x3 영역과 출입구를 건드리지 않는다.

## 데이터와 책임

`MazeBalanceSettings.SpecialRoom3x3Prefabs`를 등장 가능한 방 종류의 목록으로 사용한다. 새 ScriptableObject는 첫 버전에 필요하지 않다.
현재 `MazeRoom.TemplateIndex`는 초기 생성 때 선택한 프리팹 목록의 위치를 가리킨다. 동적 생성에서는 방 인스턴스 식별자와 **프리팹 종류 식별자**를 분리하고, 종류 식별자가 안정적으로 프리팹과 `MazeRoomTemplate`을 찾도록 바꾼다.
프리팹의 `MazeRoomEntranceMarker`는 원본 방향을 정의한다. 새 방마다 선택한 0/90/180/270도 회전을 논리 출입구와 실제 프리팹에 똑같이 적용한다.

새 계산 컴포넌트(예: `SpecialRoomReplacer`)가 후보 선정, 교체 시험, 경로 검증을 맡는다. Unity 오브젝트의 생성과 제거는 `MazeRenderer`의 별도 방 교체 API가 맡는다.
`MazeRegionChanger`는 일반 타일 사이 벽 변경만 담당하며 특수방 교체를 호출하거나 방 프리팹을 선택하지 않는다.

## 한 번의 교체 절차

1. 현재 특수방 중 플레이어·미라가 점유하지 않고 안전 반경 밖에 있는 방을 고른다. 화면에 보이는 방을 피하는 규칙은 플레이테스트 후 추가할 수 있다.
2. 일반 통로에서 새 3x3 영역을 찾는다. 다른 방과 최소 한 칸을 띄우고, 보물방·출구·시작점·캐릭터 및 보호 칸과 겹치지 않아야 한다. 회전한 문 바깥에도 통로 공간이 있어야 한다.
3. 현재 격자의 복사본에서 기존 특수방의 9칸과 출입구 연결을 제거한다. 옛 자리는 `Normal`로 바꾸고 주변과 이어지는 일반 통로를 재구성한다.
4. 새 영역에 걸친 기존 일반 통로를 정리한 뒤 선택한 종류·회전의 새 방을 예약하고, 표시된 출입구만 주변 통로에 연결한다. 방 내부 9칸은 하나의 프리팹 점유 영역으로 유지한다.
5. 플레이어의 현재 칸에서 출구, 보물방, 모든 특수방을 포함한 전체 격자 칸으로 이동할 수 있는지 검사한다. 실패하면 다른 위치·회전·종류를 정해 제한된 횟수만 재시도한다.
6. 검증된 복사본만 현재 격자로 확정한다. 같은 프레임에 옛 방 프리팹을 없애고 옛 자리에 일반 타일을 만들며, 새 자리의 일반 타일을 치우고 새 방 프리팹을 만든다. 주변 벽을 갱신한 뒤 `GeometryChanged`를 한 번 보낸다.

후보 선정과 재시도에 시드를 사용해 같은 초기 미로·캐릭터 위치·변화 순서에서는 같은 결과가 나오도록 한다. `K`가 2 이상이면 `K`쌍 전체를 하나의 복사본에서 검증하고 한꺼번에 확정한다. 일부만 성공했다는 이유로 특수방 수를 잠시라도 줄이지 않는다.

## 실패와 게임 오브젝트 정책

- 후보가 없거나 경로가 끊기면 원본 격자와 화면은 전혀 바뀌지 않는다. 다음 주기에 다시 시도한다.
- 플레이어 또는 미라가 들어 있는 방은 제거하지 않는다. 새 방도 캐릭터 위치나 안전 반경 위에 만들지 않는다.
- 사라지는 특수방 안의 상호작용 오브젝트는 방과 함께 제거된다. 유지해야 할 진행 상태가 생긴다면 별도 게임 상태에 저장하고, 새 방 프리팹 생성 시 복원하는 정책을 먼저 정한다.
- `MazeRenderer.Build`로 미로 전체를 다시 만들지 않는다. 보물, 플레이어 주변 오브젝트와 기존 방 상태까지 초기화될 수 있으므로 변경된 두 영역만 교체한다.
- NavMesh 재생성은 선택적인 `Monster/MazeNavMeshUpdater`가 `GeometryChanged`를 받아 처리한다. 방 교체가 실패했을 때는 재생성하지 않는다.

## 현재 코드에서 필요한 작업 순서

아래 1~4단계는 구현했다. 현재는 주기마다 특수방 1개를 교체하며, 유효 후보가 없으면 그 주기에는 일반 통로 변경만 진행한다. `K > 1` 일괄 교체와 화면 밖 방 우선 선정은 후속 범위다.

1. `MazeGrid`에 방 제거와 격자 복사/확정 수단을 추가한다. `rooms`, `roomCells`, 9칸의 종류·보호 상태, 양쪽 벽 상태가 항상 일치해야 한다.
2. 초기 방 배치의 프리팹 선택 정보를 안정적인 종류 목록으로 정리하고, 런타임 후보 선정·통로 재구성·경로 검증을 구현한다.
3. `MazeRenderer`에 변경된 영역의 일반 타일과 방 프리팹만 교체하는 API를 추가한다.
4. 실행 컨트롤러에서 일반 통로 변경과 특수방 교체를 같은 주기에 조율하되 계산은 별도 호출로 유지한다. 렌더러의 일괄 갱신 경계에서만 `GeometryChanged`를 한 번 보내 NavMesh가 중복 재생성되지 않게 한다.

## 검증 기준

- 성공 전후 특수방 수는 항상 설정값이고, 보물방·출구·시작점과 방 점유 영역은 손상되지 않는다.
- 새 방의 회전된 논리 출입구와 프리팹 문 방향이 일치하며 모든 격자 칸이 도달 가능하다.
- 캐릭터가 방 안에 있거나 적합한 새 3x3 공간이 없을 때는 아무것도 바뀌지 않는다.
- 같은 시드에서 방 종류·위치·회전·벽이 재현된다. 여러 시드에서 실패 복구와 1개 교체를 검사한다. `K > 1` 일괄 교체 검증은 후속 범위다.
- Unity Play Mode에서 프리팹 제거/생성, 콜라이더, 보물 상태, NavMesh 갱신과 장면 전환을 확인한다.
